# Talabat Captains Hub — تطبيق الكباتن (عرض ونسخ فقط)

صفحة ويب خفيفة (PWA) يفتحها الكباتن من الموبايل أو الكمبيوتر **بدون حساب على Rooster / Hurrier**.
البيانات يرفعها الأدمن من الإضافة (مشفّرة) إلى GitHub، والتطبيق يقرأها فقط.

```
mobile_app/
├─ captain.html          ← التطبيق (ملف واحد)
├─ manifest.webmanifest  ← لتثبيته كتطبيق على الموبايل
├─ sw.js                 ← تخزين هيكل التطبيق فقط (البيانات لا تُخزَّن)
├─ icons/                ← أيقونات التطبيق
└─ README.md
```

---

## خطوات التشغيل (مرة واحدة فقط)

### 1) أنشئ مستودع GitHub
1. من github.com اضغط **New repository** واختر اسماً (مثال: `captains-hub`).
2. اختر **Add a README file** (ضروري — المستودع الفارغ لا يقبل الرفع من الإضافة).
3. **عام (Public) أو خاص (Private)؟** البيانات مشفّرة في الحالتين. الخاص أفضل، لكن GitHub Pages
   على المستودعات الخاصة يحتاج خطة مدفوعة (Pro/Team). لو حسابك مجاني استخدم Public — لا مشكلة لأن كل
   الملفات في مجلد `data/` مشفّرة بـ AES-256.

### 2) ارفع ملفات التطبيق
داخل المستودع: **Add file ▸ Upload files** ثم اسحب **محتويات** مجلد `mobile_app/`
(`captain.html` و `manifest.webmanifest` و `sw.js` ومجلد `icons`) واضغط **Commit**.
> ارفعها في الجذر (Root) للمستودع، وليس داخل مجلد فرعي.

### 3) فعّل GitHub Pages
**Settings ▸ Pages ▸ Source: Deploy from a branch ▸ Branch: `main` / `(root)` ▸ Save.**
بعد دقيقة ستظهر الصفحة على: `https://USERNAME.github.io/REPO/` (لو اسم المستودع `USERNAME.github.io` يكون الرابط `https://USERNAME.github.io/`).

### 4) أنشئ GitHub Token (للإضافة فقط)
**GitHub ▸ Settings ▸ Developer settings ▸ Personal access tokens ▸ Fine-grained tokens ▸ Generate new token**
- Repository access: **Only select repositories** ← اختر المستودع فقط.
- Permissions ▸ Repository permissions ▸ **Contents: Read and write**.
- انسخ التوكن (يبدأ بـ `github_pat_`). لا تشاركه مع أحد — يُحفظ داخل إعدادات الإضافة على جهازك فقط.

### 5) أنشئ Google Client ID (لتسجيل دخول الكباتن)
1. افتح https://console.cloud.google.com وأنشئ Project جديد.
2. **APIs & Services ▸ OAuth consent screen**: اختر **External**، املأ الاسم والإيميل، ثم احفظ.
   ثم اضغط **Publish app** (Publishing status = *In production*) — وإلا لن يستطيع الدخول إلا من تضيفهم يدوياً كـ Test users.
3. **APIs & Services ▸ Credentials ▸ Create credentials ▸ OAuth client ID ▸ Web application**.
4. في **Authorized JavaScript origins** أضف: `https://USERNAME.github.io` (بدون أي مسار بعده).
5. انسخ الـ **Client ID** (ينتهي بـ `.apps.googleusercontent.com`).

### 6) ثبّت الإضافة المحدّثة
1. فك ضغط الملف، وفي Chrome افتح `chrome://extensions` وفعّل **Developer mode**.
2. **Load unpacked** ثم اختر مجلد `extension/` (لو الإضافة القديمة مثبتة: احذفها أو اضغط Reload).
3. افتح تاب **Rooster** وسجّل الدخول (الإضافة تحتاج جلسة الأدمن لسحب البيانات).

### 7) اضبط المزامنة من الإضافة
افتح لوحة الإضافة ◂ تبويب **السجل والإعدادات** ◂ كارت **🌐 مزامنة تطبيق الكباتن**:
1. املأ: **Owner** (اسم حسابك) و **Repo** و **Branch** (`main`) و **GitHub Token** و **Google Client ID**.
2. اكتب **الإيميلات المسموح لها** (إيميل Google لكل كابتن، كل إيميل في سطر).
3. اضغط **🔑 توليد** لإنشاء مفتاح الوصول، ثم **💾 حفظ**.
4. اضغط **🔌 اختبار GitHub** — يجب أن تظهر علامة ✔.
5. اضغط **⬆ مزامنة الكل**. أول مرة قد تأخذ عدة دقائق (حسب عدد المناديب) — بعدها المزامنات أسرع كثيراً لأن الإضافة ترفع **الملفات التي تغيّرت فقط**.

### 8) وزّع الرابط على الكباتن
اضغط **🔗 نسخ رابط الكباتن** وأرسله لهم (واتساب مثلاً). الرابط يحتوي المفتاح بعد علامة `#` فلا يصل لأي سيرفر.
عند الفتح: يسجّل الكابتن دخوله بحساب Google ← إن كان إيميله ضمن القائمة تظهر البيانات.
للتثبيت على الموبايل: من قائمة المتصفح اختر **Add to Home screen / تثبيت التطبيق**.

## ملاحظات مهمة

**الأمان — اقرأها**
- كل ملفات `data/` مشفّرة (AES-GCM-256) والمفتاح لا يُرفع أبداً؛ يوجد فقط في الرابط الذي ترسله للكباتن وفي إعدادات الإضافة عندك.
- فحص قائمة الإيميلات يتم داخل المتصفح (لأن الموقع ثابت بدون سيرفر)، لذلك **المفتاح هو القفل الحقيقي**:
  إن وصل الرابط لشخص غير مصرّح له فسيستطيع قراءة البيانات. للإلغاء: اضغط **🔑 توليد** في الإضافة ثم **مزامنة الكل**،
  وأرسل الرابط الجديد للكباتن الحاليين فقط (الرابط القديم يتوقف فوراً).
- لإيقاف كابتن معيّن: احذف إيميله من القائمة ثم زامن (يمنعه من الدخول عبر التطبيق). ولمنع شخص حصل على المفتاح فعلاً يلزم تغيير المفتاح.
- لا يوجد في التطبيق أي زر أو نافذة للإيقاف أو فك الإيقاف أو تغيير الباسورد أو التعديل — عرض ونسخ فقط.
- الصور والأرقام القومية بيانات شخصية: لا تنشر الرابط في مجموعات عامة.

**الأوردرات**
- التطبيق يعرض الأوردرات التي تمت مزامنتها فقط: أي أوردر فحصته أنت في تبويب الأوردرات بالإضافة (يُضاف تلقائياً)،
  أو أكواد لصقتها في خانة "أكواد أوردرات إضافية". يُحتفظ بآخر 14 يوماً (حتى 500 أوردر).
- المندوب **الأساسي** = أول مندوب ظهر على الأوردر زمنياً، و**الشريك/البديل** = من أُضيف بعده (تحويل/مشاركة/إعادة إسناد). تظهر أيضاً آخر حالة لكل منهما.
- الأوردرات غير المنتهية تُعاد قراءتها في كل مزامنة (بعد 10 دقائق من آخر قراءة)، والمنتهية تبقى كما هي.

**المزامنة**
- يمكن تفعيل **مزامنة تلقائية** (كل 15 دقيقة إلى 3 ساعات) من نفس الكارت؛ تعمل طالما Chrome مفتوح وجلسة Rooster نشطة.
- بيانات المناديب (الهاتف/القومي/SP/الصورة) تُجدَّد كل 6 ساعات؛ حالة الإيقاف تُجدَّد في كل مزامنة. زر **♻ مزامنة كاملة** يتجاهل الكاش.
- GitHub Pages قد يتأخر من 1 إلى 10 دقائق بين الرفع وظهور البيانات للكباتن. زر 🔄 في التطبيق يعيد التحميل.
- المناديب الظاهرون هم أصحاب العقود النشطة. أي مندوب غير نشط ظهر على أوردر يُضاف تلقائياً كحالة "غير نشط".

**حل المشاكل**
| المشكلة | الحل |
|---|---|
| "جلسة Rooster منتهية" | افتح تاب Rooster وسجّل الدخول ثم أعد المزامنة |
| "المستودع فارغ" | أضف README في المستودع |
| 404 / 403 من GitHub | تأكد من اسم المستودع والفرع وصلاحية Contents: Read and write للتوكن |
| "مفتاح الوصول غير صحيح" عند الكابتن | تم تغيير المفتاح — أرسل له الرابط الجديد |
| زر Google لا يعمل | تأكد أن Authorized JavaScript origin = `https://USERNAME.github.io` تماماً وأن التطبيق *In production* |
